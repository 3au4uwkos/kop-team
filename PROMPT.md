# Промпт: техническая доработка сайта kopeykin-sambo

Ты — разработчик, дорабатывающий сайт-визитку тренера по самбо (Копейкин П. С., г. Тула).
Выполняй задачи по этапам, в указанном порядке. У каждой задачи есть критерий приёмки —
задача не считается сделанной, пока критерий не выполнен.

## Правило №0: никаких push

Работа ведётся строго локально. **Запрещено выполнять `git push` в любой удалённый
репозиторий** (`origin`/GitHub, `russian`/GitVerse) — ни в master, ни в другие ветки,
включая force-push и push тегов. Коммиты остаются локальными; публикацию выполняет
только владелец вручную. Причина: репозиторий публичный (GitHub Pages), а часть
локальных файлов — включая этот промпт — не предназначена для публикации.

## Контекст и зафиксированные решения

- Текущий стек: HTML + CSS + vanilla JS (ES-модули), 10 из 11 секций подгружаются AJAX'ом
  (`js/lazy-loader.js`) — это главная проблема для SEO и подлежит демонтажу.
- Хостинг: **GitHub Pages**, целевой домен **kopeykin-sambo.ru**.
- Целевой стек: **Astro (SSG)** — статическая генерация, ноль JS-фреймворка в браузере.
  Nuxt отклонён (без блога избыточен), чистый HTML отклонён (~10 страниц с общей шапкой
  не синхронизировать руками).
- **Целевая аудитория — Тула** (не Москва).
- **Блога не будет.** Сторонней рекламы не будет. Персональные данные не собираем:
  ни форм, ни cookies — запись только переходом в мессенджеры.
- **Сайт остаётся одностраничным**: главная со всеми секциями + служебные страницы
  (faq, contacts, privacy, terms, 404). Отдельные страницы направлений не создаются —
  они в резерве (см. 3.1).
- **Ссылка на Instagram остаётся** — обязательно с маркировкой (см. задачу 1.2).
- Интерактив (reveal, счётчики, карусели) остаётся vanilla-модулями, подключаемыми
  через обычные `<script>` в компонентах Astro.

## Вне скоупа этого промпта

Все задачи, связанные с медиа, ведутся владельцем отдельно и здесь не выполняются:
подготовка/оптимизация фото и видео, OG-изображения, замена фото-плейсхолдеров,
исправление битых ссылок на favicon/og-image, согласия на публикацию фото.
Разметку под будущие медиа (`<picture>`, poster у видео) закладывать можно, сами файлы — нет.

## Этап 1. Быстрые правки текущей версии (до миграции)

### 1.1. Устранить гео-конфликт Москва/Тула
Сейчас `<title>` говорит «в Москве», description и контент — «Тула», keywords — «самбо москва».
- Переписать `<title>`: `Тренер по самбо в Туле — Копейкин Павел Сергеевич | Мастер спорта`.
- Согласовать description, OG-теги, twitter-теги и JSON-LD: везде Тула.
- Удалить `<meta name="keywords">` целиком (поисковики игнорируют, конкурентам — подсказка).
- В JSON-LD исправить «в Тула» → «в Туле».

**Приёмка:** в исходнике главной нет ни одного упоминания Москвы в метаданных; город
одинаков во всех разметках.

### 1.2. Маркировка Instagram
Instagram принадлежит Meta, признанной экстремистской организацией в РФ, ссылка без пометки — риск.
- У кнопки Instagram в `sections/contacts.html` поставить звёздочку, под блоком соцсетей —
  сноску мелким шрифтом: «*Принадлежит Meta Platforms Inc., признанной экстремистской
  организацией; её деятельность запрещена на территории РФ».
- WhatsApp маркировки не требует. `sameAs` в JSON-LD не трогать.

**Приёмка:** видимая ссылка на Instagram нигде не появляется без сноски.

### 1.3. Полный rel на внешних ссылках
Во всех ссылках с `target="_blank"` заменить `rel="noopener"` на `rel="noopener noreferrer"`.

**Приёмка:** grep по репозиторию не находит `target="_blank"` без `noreferrer`.

## Этап 2. Миграция на Astro (SSG)

### 2.1. Каркас и перенос
1. `npm create astro@latest` — шаблон minimal, статический вывод (по умолчанию).
2. Общий `src/layouts/Base.astro`: head-мета (title/description/OG/canonical/JSON-LD —
   пропсами для каждой страницы), навбар, футер, подключение глобальных стилей.
3. Каталог `css/` переносится как есть (tokens, base, nav, animations, sections/*).
4. `sections/*.html` → `src/components/sections/*.astro` (синтаксис совместим с HTML,
   перенос почти копипастом). Главная страница рендерит все секции статически.
5. **Удалить**: `js/lazy-loader.js`, AJAX-плейсхолдеры, инлайн-стили `style="min-height:…"`,
   `sitemap.xml` (заменит интеграция), динамическую подгрузку CSS из `js/utils.js`.
6. JS-модули (reveal, счётчики, карусели, nav, smooth-scroll) подключить через `<script>`
   в соответствующих компонентах — Vite соберёт и минифицирует.
7. Vendor-библиотеки перевести на npm-пакеты (см. 2.3) — Dependabot будет следить за ними.

**Приёмка:** `curl` собранной главной возвращает весь текст всех секций без исполнения JS;
в бандле нет JS-фреймворка; `npm run build` проходит без ошибок.

### 2.2. SEO-обвязка сборки
- Интеграция `@astrojs/sitemap` + `site: 'https://kopeykin-sambo.ru'` в `astro.config.mjs`.
- `robots.txt` в `public/` (Allow всем, ссылка на sitemap).
- Файл `public/CNAME` с содержимым `kopeykin-sambo.ru`.

**Приёмка:** в собранной статике есть корректные sitemap-index/sitemap, robots.txt, CNAME;
в sitemap нет URL с `#фрагментами`.

### 2.3. Чистка веса
- **Swiper**: либо переписать карусели на CSS scroll-snap + ~30 строк JS для точек
  (предпочтительно), либо импортировать из npm только ядро и нужные модули.
  Бюджет: суммарный JS+CSS каруселей ≤ 30 КБ.
- **Шрифты**: удалить из `vendor/fonts/fonts.css` и `files/` неиспользуемые subsets
  (greek, vietnamese, latin-ext); добавить `<link rel="preload" as="font">` для двух
  критичных woff2 первого экрана (Oswald cyrillic 500/600, Manrope cyrillic 400).
- **Прелоадер**: убрать `setTimeout` на 1200 мс — скрывать сразу по `load`,
  CSS-переход 300–400 мс.

**Приёмка:** суммарный вес JS страницы уменьшился минимум вдвое против текущего;
шрифты первого экрана в водопаде стартуют до окончания парсинга CSS.

### 2.4. Безопасность в Layout
- Meta-CSP в `<head>` (GitHub Pages не даёт HTTP-заголовков):
  `default-src 'self'; img-src 'self' data:; style-src 'self'; script-src 'self';
  base-uri 'self'; form-action 'none'; frame-ancestors 'none'`.
- `<meta name="referrer" content="strict-origin-when-cross-origin">`.

**Приёмка:** в консоли браузера нет CSP-нарушений ни на одной странице.

### 2.5. Деплой на GitHub Pages
- GitHub Actions workflow на официальном `withastro/action` → `actions/deploy-pages`,
  триггер — push в master.
- В настройках Pages: Source = GitHub Actions.

**Приёмка:** push в master автоматически публикует сайт; сборка на чистом раннере проходит.

## Этап 3. Страницы

### 3.1. Текстовое усиление главной (вместо страниц направлений)
Решение владельца: сайт одностраничный, отдельные страницы направлений НЕ создаются.
Весь текстовый вес несёт главная:

- в каждую секцию направления (боевое самбо, спортивное самбо, ударная техника,
  утренняя зарядка, ОФП 4–6, подростки) добавить развёрнутый текстовый блок:
  программа, для кого, как проходит тренировка. Допустимо сворачивать в
  `<details>`/«Подробнее», чтобы не ломать композицию — поисковики такой текст читают;
- у каждой секции — содержательный `<h2>` с вхождением запроса (например,
  «Боевое самбо для взрослых и детей в Туле»), без переспама;
- черновики текстов согласуются с владельцем, структуру и разметку делает разработчик.

**Резерв на будущее:** каждая секция — отдельный Astro-компонент. Если через 3–4 месяца
Яндекс.Вебмастер покажет, что запросы вида «самбо для детей тула» не ранжируются,
под них добавляются отдельные страницы из готовых компонентов — но только с уникальным
расширенным текстом, не копией секции (иначе это дубль и пользы не даст).

**Приёмка:** каждая секция направления на главной содержит ≥ 1000 знаков текста;
у всех секций содержательные h2; sitemap содержит только главную и служебные страницы.

### 3.2. Служебные страницы
- `/privacy/` — политика конфиденциальности: сайт не собирает ПДн, форм нет, cookies нет,
  связь через сторонние мессенджеры (их политики — на их стороне), контакт для вопросов.
- `/terms/` — условия использования: информация не оферта, расписание и цены — в личных
  сообщениях, за контент сторонних мессенджеров сайт не отвечает.
- `/faq/` — 15–20 реальных вопросов (возраст, первая тренировка, стоимость, форма,
  травмоопасность, расписание, пробное занятие…) с разметкой schema.org **FAQPage**.
- `/contacts/` — мессенджеры (с маркировкой Instagram), адрес зала, как добраться;
  карта — статичной картинкой-ссылкой на Яндекс.Карты, без тяжёлого embed.
- `404` — `src/pages/404.astro`: «Такой страницы нет» + ссылки на главную (и её
  секции-якоря), кнопка «Записаться».
- Ссылки на privacy/terms/faq/contacts — в футере каждой страницы.

**Приёмка:** все страницы в sitemap; FAQ проходит Google Rich Results Test;
несуществующий URL отдаёт фирменную 404.

### 3.3. Реквизиты исполнителя
Запросить у владельца налоговый статус (самозанятый / ИП) и добавить в футер и на
/contacts/: ФИО, статус, ИНН (для ИП — ОГРНИП). До получения данных — оставить
закомментированный плейсхолдер и TODO.

**Приёмка:** блок реквизитов свёрстан; данные вставлены или помечены TODO с блокером «ждём владельца».

### 3.4. Доработка структурированных данных
- SportsActivityLocation: полный address (улица, индекс), geo, openingHours, telephone, priceRange.
- FAQPage на /faq/; BreadcrumbList на служебных страницах.
- JSON-LD собирается в Layout из пропсов страницы.

**Приёмка:** Google Rich Results Test и валидатор Яндекс.Вебмастера — без ошибок.

## Этап 4. Мобильная адаптация

Целевые вьюпорты: 360×800, 390×844, 768×1024 + альбомная ориентация.

1. **Вьюпорт-единицы:** заменить `min-height: 100vh` на `100svh` (с fallback `100vh`
   строкой выше); учесть `env(safe-area-inset-*)` в навбаре и дровере.
2. **Дровер:** блокировка скролла фона при открытом меню, закрытие по Esc и тапу вне,
   focus-trap, возврат фокуса на бургер, синхронный `aria-expanded`.
3. **Тап-цели ≥ 44×44 px:** дотсы каруселей, кнопка play, соц-ссылки, бургер —
   увеличивать кликабельную зону паддингом/псевдоэлементом, не визуал.
4. **Круг «Направления»:** ниже ~560 px заменять SVG-диаграмму вертикальным списком
   из трёх карточек с теми же данными и переходами.
5. **Hover vs touch:** hover-эффекты обернуть в `@media (hover: hover) and (pointer: fine)`;
   на touch — свайп в галереях, для секторов направлений: первое касание раскрывает,
   второе переходит.
6. **Типографика:** display-заголовки на `clamp()`; `overflow-wrap` для длинных слов;
   фоновые слова-декорации не должны давать горизонтальный скролл (`overflow-x: clip`).
7. **Финальный прогон** по чек-листу на реальных Android и iPhone (не только DevTools):
   читаемость, свайпы, 3G-throttling, deep-links `t.me`/`wa.me` открывают приложения.

**Приёмка:** ни на одном вьюпорте нет горизонтального скролла; Lighthouse tap targets
зелёный; чек-лист п.7 пройден на двух реальных устройствах.

## Этап 5. Декор и анимации

Направление: «спортивная афиша» — крупная кондензед-типографика, разметка как на
борцовском ковре, один алый акцент. Всё движение — только transform/opacity,
`prefers-reduced-motion` уважается везде (уже реализовано — не сломать).

1. **Моушн-токены:** в tokens.css — `--dur-fast/base/slow`, `--ease-out`; перевести на них
   все анимации (reveal, счётчики, hover, прелоадер, карусели). Сырых длительностей в CSS
   быть не должно.
2. **Параллакс фоновых слов:** каждой секции — своё фоновое слово (САМБО, ВЫБОР, БОЙ…),
   движущееся медленнее контента: CSS scroll-driven animations (`animation-timeline: view()`)
   с fallback на статичное слово; без JS.
3. **Микровзаимодействия:** CTA «Записаться» — заливка алым на hover; стрелки соц-ссылок —
   штрих-анимация stroke-dashoffset; подчёркивания навигации от центра; активная точка
   карусели растягивается в полоску.
4. **Фактура:** зерно SVG feTurbulence (data-URI, opacity 0.03–0.05) на ink-секциях;
   тонкие линии-оси/дуги (отсылка к кругу ковра) между секциями — без единого
   дополнительного сетевого запроса.
5. **Прелоадер-титр:** слово «КОПЕЙКИН» появляется line-wipe'ом и уходит вверх, суммарно
   ≤ 400 мс (вместе с задачей 2.3).

**Приёмка:** FPS при скролле не падает ниже 60 (DevTools Performance);
при `prefers-reduced-motion: reduce` анимации отключены; движение везде в едином ритме токенов.

## Чек-лист владельца (вне репозитория, руками)

Эти шаги не делаются кодом — выполняет владелец; разработчик напоминает и проверяет результат:

1. **Отозвать GitHub-токен**, вшитый в URL git remote в локальном `.git/config`
   (Settings → Developer settings → Tokens), перейти на Git Credential Manager.
2. GitHub-репозиторий: включить Secret scanning + Push protection, Dependabot alerts,
   запрет force-push в master.
3. DNS домена: 4 A-записи apex → 185.199.108.153…185.199.111.153, CNAME `www` →
   `3au4uwkos.github.io`; в Settings → Pages указать домен, включить **Enforce HTTPS**.
4. **Яндекс.Вебмастер** (приоритет №1 для Тулы): добавить сайт, подтвердить права,
   отправить sitemap. **Яндекс.Бизнес**: карточка организации на Картах. Дублировать в 2ГИС.
5. **Google Search Console**: домен-ресурс через DNS TXT, отправить sitemap.
   **Bing Webmaster**: импорт из GSC (покрывает Bing/Yahoo/DuckDuckGo).
6. **Яндекс.Метрика** — только в связке: одновременно добавить в /privacy/ раздел про
   метрику и cookie-уведомление на сайт; цели — клики по кнопкам мессенджеров.
