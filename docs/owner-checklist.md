# Чек-лист владельца

Эти шаги кодом не делаются — их выполняет владелец руками.
Разработчик проверяет результат.

## 1. Безопасность репозитория — сделать первым

- [ ] **Отозвать GitHub-токен**, вшитый в URL `git remote` в локальном
      `.git/config`: GitHub → Settings → Developer settings →
      Personal access tokens → Revoke. Репозиторий публичный, токен в конфиге
      живёт на диске в открытом виде.
- [ ] Перевести remote на HTTPS без токена и подключить
      Git Credential Manager:
      ```
      git remote set-url origin https://github.com/<user>/<repo>.git
      ```
- [ ] Repository → Settings → Code security: включить **Secret scanning**
      и **Push protection**.
- [ ] Включить **Dependabot alerts** (следит за astro и @astrojs/sitemap).
- [ ] Settings → Branches → Add rule для `master`: запретить force-push.

## 2. Публикация

- [ ] Settings → Pages → **Source = GitHub Actions**
      (иначе workflow соберёт сайт, но не опубликует).
- [ ] DNS домена `kopeykin-sambo.ru`:
      - 4 A-записи на apex: `185.199.108.153`, `185.199.109.153`,
        `185.199.110.153`, `185.199.111.153`;
      - CNAME `www` → `3au4uwkos.github.io`.
- [ ] Settings → Pages → Custom domain: указать `kopeykin-sambo.ru`,
      дождаться проверки, включить **Enforce HTTPS**.
- [ ] Файл `public/CNAME` уже в репозитории — трогать не нужно.

- [ ] **GitVerse (зеркало):** репозиторий на gitverse.ru → Настройки →
      Страницы → включить, Источник = **«Воркфлоу»**, сохранить.
      Репозиторий должен быть публичным, CI/CD — включён. Без этого
      деплой падает с `failed to create deployment: 404 Not Found`.
      Затем CI/CD → workflow «GitVerse Pages» → запустить вручную.
      Адрес зеркала: `https://3au4uwkos.gitverse.site/kop-team/`.
